# B200 Benchmark Results

These results were measured on a Vast.ai 1x B200 instance:

- GPU: NVIDIA B200, compute capability 10.0
- Driver: 580.126.09
- CUDA: 13.0
- Python: 3.12.3
- MAX/Modular: 26.4.0.dev2026051206
- PyTorch: 2.11.0+cu130
- `ptxas`: `/usr/local/cuda/bin/ptxas`

The GPU smoke run passed:

```text
15 passed, 2 warnings in 833.11s (0:13:53)
```

The long first-run time was from MAX building its interpreter op cache for the
fresh virtual environment. Later runs reused that cache.

## Larger CUDA Workload

```bash
MODULAR_NVPTX_COMPILER_PATH=/usr/local/cuda/bin/ptxas \
uv run --no-sync python benchmarks/pytorch_compile.py \
    --device cuda --batch-size 1024 --input-dim 256 --hidden-dim 512 \
    --output-dim 64 --warmup-steps 5 --steps 20 --repeats 3 \
    --torch-compile-mode max-autotune
```

```text
engine                       status  compile_s  median_ms  steps/s  samples/s  initial_loss  final_loss
---------------------------  ------  ---------  ---------  -------  ---------  ------------  ----------
torch_eager                  ok      0.000000   0.464      2157.10  2208869.3  0.981289      0.665561
torch_compile[max-autotune]  ok      19.065556  0.487      2055.19  2104514.0  0.981289      0.665561
```

The larger workload ran after the small workload, so MAX/Mojo interpreter and
compiler caches were already warm. Treat the larger `max_compile` compile time
as a warm-cache number.

PyTorch `max-autotune` printed several Triton candidate failures because some
candidate kernels exceeded the B200 resource limit:

```text
OutOfMemoryError: out of resource: triton_mm Required: 262144 Hardware limit:232448
```

The benchmark still completed with `ok` status and selected valid kernels.

## PyTorch Fullgraph Check

The same larger workload with `--torch-fullgraph` did not complete for the
current PyTorch benchmark step:

```bash
MODULAR_NVPTX_COMPILER_PATH=/usr/local/cuda/bin/ptxas \
uv run --no-sync python benchmarks/pytorch_compile.py \
    --device cuda --batch-size 1024 --input-dim 256 --hidden-dim 512 \
    --output-dim 64 --warmup-steps 5 --steps 20 --repeats 3 \
    --torch-compile-mode max-autotune --torch-fullgraph
```

```text
torch_compile[max-autotune][fullgraph] error: Unsupported: Attempted to inline function marked as skipped
Explanation: Dynamo developers have intentionally marked that the function `Optimizer.zero_grad` should not be traced.
```

This is a limitation of the current benchmark's PyTorch train-step shape, not a
B200 or MAX failure. A fair `fullgraph=True` comparison needs a more functional
PyTorch step that avoids tracing `Optimizer.zero_grad`.
